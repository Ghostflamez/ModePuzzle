# 模组拼合实验室 · ModePuzzle

**English:** see [README.en.md](README.en.md). 界面支持中文 / English，右上角切换。

> **非官方粉丝工具**，与 Questing Goose Studio 及《Probably Stolen》（深空当铺：可能是偷的）官方无关。不包含任何游戏素材：模组像素画为原创，说明文字自行撰写，仅沿用游戏中的名词。代码以 [MIT](LICENSE) 许可发布；界面字体的许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

纯浏览器应用，无运行时依赖。默认 7×5 去除四角，共 31 格（见 `src/config/ui.js`）；支持自定义 1–10 行列、最多 100 个候选插入件。数据仅保存到浏览器 localStorage，支持 JSON 导入、导出与结果导出。

## 使用

1. 添加模组：点击 5×5 画板定义共边连通的形状，填写三项初始属性、词条和重复数量。通常是 5 格，也允许其他面积以扩展。
2. 添加辅助节点：固定 1×2，可设置重复数量。初始属性默认为零。
3. 选择效率、质量、性能或自定义。自定义可分别填写三个属性的上下界（单侧或双侧留空均可），按填写值严格判断。先满足全部范围，再最大化首要属性；首要相同才最大化次要属性，次要可不设置。允许冗余表示可舍弃候选件；否则要求全部放入。两种情况都允许空格。卡片上的「锁定一个」只转换一件：原堆叠减一，已有同类锁定条目加一，没有则新建；「解锁一个」反向操作。锁定件被排除，必选件必须用到；两种状态使用独立字段。
4. 选择时长并开始优化。输出彩色编号布局、三属性总分、逐件分解、相邻对象、坐标、旋转、镜像与未用数量。
5. 点击布局中的插入件，左侧对应类型的卡片高亮并移到顶部，显示选中实例的布局编号。只重排显示，存档顺序、数量和属性均不变。
6. 结果的属性明细下方可「锁定本次布局中的所有插入物」，将结果实际用到的副本转为锁定排除状态，后续优化不再使用；未用副本不受影响。锁定不占用插槽、不固定位置。解除全部锁定后恢复参与优化，其他条目的必选标记保持不变。
7. 限时结束仅说明找到的最佳可行值；只有精确搜索完成才显示“已证明全局最优”。不限时仍可能很慢，可停止。

演示数据仅用来试用，并非从截图识别出的真实属性。

纯前端，无运行时依赖、无后端，计算在浏览器的 Web Worker 中完成。

```sh

npm test                                      # Node 内置测试

```

### Windows 桌面版（exe）

```sh
python -m pip install pyinstaller pywebview pillow
python scripts/build_exe.py                   # 生成 release/ModePuzzle-v<版本>.exe
```

- 版本号只在 `src/config/app-info.js` 修改（页脚、窗口标题、exe 文件属性都读取它；`package.json` 需手动同步）。
- exe 用系统自带的 WebView2 打开独立窗口（Windows 10/11 一般已预装），页面由内置服务提供：优先用端口 `42173`，被占用时自动换一个空闲端口。同一时间只允许运行一个实例。

源码使用 ES modules 与模块 Worker，不能直接用 file:// 打开 `src/index.html`；需要离线使用时用构建出的单文件。

## 已实现规则（已与游戏程序核对）

计分与游戏程序 `Assembly-CSharp.dll` 中的 `ModuleEffectHelper` 逐条对照（2026-11-05，只读反编译）。游戏为每件插入件保存整数临时值 `TEMP = BASE`，再由各效果累加，全部是 C# 整数运算（除法向零截断）：

| 效果 | 游戏代码 | 本程序 |
|---|---|---|
| 侧边挂载 | `IsTouchingLeft`（形状 minX ≤ 0）时 `TEMP += BASE*20/100` | 同，每个挂载单独截断 |
| 顶部挂载 | `IsTouchingTop`（形状 minY ≤ 0）时 `TEMP += BASE*20/100` | 同 |
| 接收器 | 数出相邻 `NODE` 件数 n，`TEMP += BASE*(10*n)/100` | 同，按节点数汇总后只截断一次 |
| 负反馈 | 相邻件负 `BASE` 求和 S，`TEMP += S/4`；生成时基础属性 ×1.25 | 同；录入值已含生成时增幅 |
| 辅助节点 | 相邻模组 `BASE` 求和 S，`TEMP = S/5`（覆盖） | 同；节点自身基础值不计入 |
| 相邻 | 形状上下左右平移一格后相交；每个邻居只算一次 | 同 |
| 系统总值 | 各模组与节点的 `TEMP` 相加 | 同 |

- 所有跨件读取都只读邻居的 `BASE`，所以计算顺序无关，加成不向邻居传播。
- 默认百分比（20 / 10 / 25 / 20）可在计分规则里调整；游戏没有乘法叠加，旧存档中的 `stack: "multiply"` 自动改为加法。
- 挂载只认舱体第 0 行 / 第 0 列：四角缺口的小边、凹边、孔洞不触发。
- 记 Z(x) 为向零取整。模组 = b + Z(0.2b)·L + Z(0.2b)·T + Z(0.1b·N) + Z(0.25·Σ相邻负基础值)；节点 = Z(0.2·Σ相邻模组基础值)。例：b = 48 同时触发两个挂载 → 48 + 9 + 9 = 66（而不是合并 40% 的 67）。
- 用游戏截图核对过的 9 件布局（效率 −296、性能 +266）作为回归测试保留。
- 明细和 JSON 中：`absorbed` 为吸收收益，`receiver` 为接收器收益（`receiverNodes` 个节点，`receiverRate` 为合计百分比），`neighbour = absorbed + receiver`。导出以 `scoringVersion: "game-integer-v5"` 标识，旧结果需重新计算，录入数据不变。

## 界面语言（中文 / English）

- 右上角的语言开关切换中文与英文，选择会被记住（也可在网址后加 `?lang=en` / `?lang=zh`）。
- 实现：所有界面文字用中文原文作键，经 `tl()`（`src/i18n/index.js`）查 `src/i18n/en.js` 得到英文；`index.html` 的静态文字在启动时整体替换。切换语言会重新载入页面。
- 英文中的游戏名词（模组、词条、机器、水质等）取自游戏自带的英文本地化表；说明性文字为本项目自行撰写的英文。导入中文存档后，机器名会按游戏英文名显示（玩家自定义的名字保持不变）。
- 字体：游戏在中文与英文下对应的角色都用 WDXL Lubrifont（英文另有 Tektur 等），本工具两种语言都用同一款 WDXL Lubrifont SC（含拉丁字母）与 Mx437 Tandy2K，许可不变。
- 新增界面文字时：写中文原文并包上 `tl()`，同时在 `en.js` 加英文；`tests/i18n.test.js` 会检查遗漏。

## 搜索与正确性

- 搜索开始前排除所有 locked:true 条目，既不占格也不参与计分或邻接。关闭允许冗余时也仅要求全部未锁定件放入。
- 枚举旋转、镜像后的全部不同朝向，以及舱体内全部合法位置。
- BigInt 占用掩码防止重叠，halo 掩码判断共边。
- 随机贪心与破坏/修复只负责提供可行下界，不负责证明最优。
- 随后按固定插入件顺序做精确深搜。相同副本按落点序号递增打破排列对称；冗余分支仅能跳过未标记的整组余下副本。启发式和精确搜索均优先安排必选件，拒绝保存缺少任何必选副本的布局，包括负总分或限时结果。
- 上界：每件取最大单件值，加上与已选件的所有正增量上界、与未选件的半数正增量上界；再按剩余面积做分数背包松弛。即使部分邻接实际上做不到，界依然安全。强制模式不丢弃负贡献。混合必选/可选模式的界放宽必选限制以保持安全；是否全部放入由独立可行性检查和不可跳过的搜索分支保证。必选件总面积或形状无法放入时返回不可行。
- 只有全部未剪枝分支完成才证明最优。限时或手动停止绝不标记为已证明。
- 比较使用 1e-9 数值容差，适合游戏属性数值，所有吸收先汇总再取整，接收器仍逐节点取整。当前最佳在同分时无第二目标偏好。
- 复杂布局是组合优化问题；最多 100 件是录入上限，并非保证该规模能迅速求得最优。

## 自定义约束与优先级

`target: "custom"` 时，使用 `custom: {bounds: [{min, max, tolerance}, ...], primary, secondary}`。每个 `min` / `max` 都可以为 `null`；`primary` 为 0/1/2，`secondary` 为 0/1/2 或 `null`，不能与首要相同。轴序为效率、质量、性能。

边界按填写值严格判断，没有浮动。

每行有「精确」「模糊」两个匹配按钮（`MATCH_MODES`）：只填了一个边界、上下界相同或都未填写时可用。启用后上下界之间出现中间值框，上下界变为只读并随中间值同步：精确为相同值，模糊为中间值 ±5。再次点击同一按钮退出，两种模式可直接切换。配置中记录为 `{min, max, match, center}`，校验要求上下界与中间值一致。旧版的「±5% 浮动」已删除：旧配置中的 `tolerance` 字段读取时忽略并清除，边界数值不变。

所有范围均是必须满足的条件，不以违反范围换取更高优先属性。全部留空时仅进行优先级优化。精确搜索维护每个属性的安全上下界，保留负数可能修正当前超限值的分支；比较使用严格的字典序（1e-9 容差），不以加权和替代优先级。启发式的罚分只用于搜索顺序，不影响最终计分、可行性和最优性证明。

测试覆盖旧存档逐字段/原字节保留、升级备份、单边/空边界、旧浮动字段的清除、严格优先级、负值修正上限，以及 28 组约束与优先级的独立小规模穷举对照。

## 单件锁定、堆叠与自动命名

- `dist/inventory.js` 集中处理堆叠、单件转移和自动编号，修改失败不影响原配置。
- 堆叠比较类型、归一化形状（格子顺序和整体偏移不影响）、三项初始数值、词条集合以及 `required`、`locked` 两种状态。不同朝向的录入形状不自动视为同形。名称与 ID 不参与比较，保留最早条目的名称，其他名称保存在 `aliases`，可在卡片名称悬停查看。额外扩展字段不同也不合并。
- `transferOne` 每次只转换一件；数量为 1 时直接改变该条目状态，随后自动合并。原堆叠为零时移除，不产生零数量条目。锁定/解锁不分配新名称。
- 锁定一个时仅清除被转移那一件的必选标记，其余副本保持原状态。解锁后恢复为普通候选，不自动设为必选。
- 名称匹配（`src/core/naming.js`）：输入的名称若等于或包含官方名称/简称（目录中的 `aliases`），自动选中该官方种类；显示名始终为官方名称，输入的其他内容作为额外标签显示，可留空。存档中 `name` 字段保存输入原文，`kind` 保存官方种类。旧数据先按名称（含合并留下的历史名称）匹配，再按形状与属性推断。
- 自动堆叠在读取存档、导入、添加、编辑、单件转移后应用；加载不重写原存档，首次保存仍备份旧字节。上限为 100 个条目、100 件总量，同一堆叠最多 100 件。

## 模组种类与外观

模组种类与游戏官方对齐（数据取自游戏程序集中的 ModuleDirectory / PreBuiltItemHelper 与中文本地化表），见 `src/config/catalog.js`：

- 通用基础模组：性能（红）、效率（绿）、质量（黄），官方形状为小方形 / 4格L / T / 3格折角。
- 通用进阶模组：超频（红）、环保（绿）、精炼（黄），官方形状为方形 / C型 / P型。
- 特殊模组：优化模组、神经核心模组（受限，3格折角 / 无限制，方形）、空白、损坏、报废。
- 水培模组（7 种）及 3D打印机、DNA编辑器、蒸发器、熔炉、警报器专用模组（1×4 或 1×2 长条）。
- 节点：节点（中）1×2、节点（小）1×1。

外观是本项目原创的像素画（`src/render/module-art.js`），由代码按模组实际占用的格子逐像素生成，不含任何游戏贴图，也不使用图片文件。每个种类按颜色和风格区分（基础、进阶、AI 核心、机器专用、节点等）；游戏中不存在的种类或形状组合显示为斜纹占位样式。

旧数据没有 `kind` 字段时，按「该形状的官方种类 + 属性正负号最接近的模板」推断，卡片标注「推断」，编辑保存后写入 `kind`。推断只影响显示，不改动任何录入数值。

词条（侧边挂载、顶部挂载、负反馈、接收器、辅助节点）使用游戏中的名称，说明文字由本项目自行撰写，百分比随当前计分规则填入；卡片上以带像素图标的彩色标签显示，布局中触发的挂载会在舱体边缘高亮。

## 不参与计分的词条

优质、劣质、过载、退化、自学习算法只改变模组自身的基础值（游戏代码：生成时 ×1.2 / ×0.8 / ×2 / ×2；过载每次使用 10% 几率变为报废模组；退化每次使用每项正向基础值 −1；自学习从 0 开始随使用增长，上限为生成值 2 倍）。录入的是游戏中当前显示的基础值，所以它们不参与计分，只用于：

- 警告：卡片和结果中提示退化、过载的风险，不做数值预测。
- 偏好：优化时在目标与优先级都相同的情况下，选用退化/过载模组更少的布局（精确搜索可证明）。
- 自学习模组的数值随使用变化，存档更新后重新导入即可得到最新值。
- 校验：编辑时按游戏限制最多 2 个词条，并禁用互斥组合；旧数据超出限制时只提示，不拒绝加载。

## 导入游戏存档与机器视图

**只读：本工具只读取存档，绝不写回游戏。**「导入游戏存档」读取 `%USERPROFILE%\AppData\LocalLow\Questing Goose Studio\Probably Stolen\save_N.es3`（只读，不会写回）。解析见 `src/core/save-import.js`，数据结构与换算均取自游戏程序：

- 物品是扁平列表，通过 `childItems` 引用；模组的 `identifier` 对应官方种类，`BONUS_PERCENTAGE_*_INT` 为基础属性，`MODULE_EFFECT1/2_TAG` 为词条。
- 机器内的位置按 `GridShape.ForwardTransform` 还原（先翻转，再按 orientation 旋转，再加偏移）。
- 模组舱：标准机器 7×5，按 `MODULE_UPGRADE_STAGE_INT` 为 26 / 31 / 35 格；蒸发器 4×4。化学类机器及化学设备模组不在范围内（`src/config/machines.js`）。
- 已收录全部 11 种带标准模组舱的原版机器（水培系统、净水器、熔炉、DNA编辑器、3D打印机、交易机、警报器、全息投影仪、湿气农场、密码解序器、酒架）与蒸发器，机器标识和可装模组类型取自 `FurnitureItemDirectory` 与各机器构造函数。
- 未收录但带 `STANDARD_MACHINE_TAG` 的机器（如模组新增的机器）按标准模组舱处理，可装类型为通用模组加上它当前已装的类型，界面中会注明。

导入后：

- 自由模组（不在任何机器中）进入候选栏；装在机器里的模组归属各自机器，其他机器的模组在优化时不可用。
- 选择一台机器：模组舱和当前排布按存档显示，并按游戏公式显示机器参数（`src/core/machine-stats.js`：作业速度、所需能量，以及性能/效率/质量与机器换算系数；交易机的耗能按其专用公式）。
- 产出效果只取自游戏程序（`MACHINE_OUTPUTS`，每项注明来源方法）：水培收获量、净化量加成、熔炉品质档位、DNA 成功率用质量、打印品质、交易成功率、警报性能、投影吸引力、湿气农场产水量与水质、酒架每日陈酿、蒸发器处理倍率与有效质量。依赖运行时条件的部分（如原水纯度、基因复杂度）只显示游戏实际使用的数值并注明用途。
- 本机器内的模组是否参与优化只由机器卡片上的锁决定：锁定时全部排除，解锁后按每件模组自己的锁定/必选设置参与；
- 机器解锁时可手动升级模组舱（每次一级，26 → 31 → 35 格），也可撤回到存档中的等级；撤回时若当前排布占用了将被移除的格子则拒绝。升级只在本工具中生效，不写回存档；机器不能安装的模组类型自动排除；手动添加的条目不参与机器视图。
- 开始优化时保存本机器排布的副本，可「恢复原排布」；「确认更改」把结果写入本机器（用到的模组移入，未用到的本机器模组回到自由模组）并删除副本。之后请在游戏中按结果摆放；重新导入存档会以存档为准覆盖。

## 数量限制

- 库存（候选栏总量）：最多 2000 件、1000 个堆叠，足以容纳整份存档。
- 单次优化：最多 100 件参与（锁定排除、装在其他机器中、机器不能安装的类型不计入），界面实时显示「参与优化 x / 100 件」。
- 实测（31 格舱）：搜索速度约随参与件数的平方下降（30 件约 9.7 万状态/秒，100 件约 0.75 万），但 5–15 秒内找到的最佳值相近；件数越多越难在时限内证明全局最优。
- 测试使用计数时钟（`tests/clock.js`），结果不受机器负载影响。

### 机器的全局锁定 / 解锁

- 机器总览里每台机器有一个锁形按钮。默认「锁定」：它的模组不会被其他机器调用。
- 「全局解锁」后，优化其他机器时可以调用它的模组（解锁前会弹出确认）；在其他机器上「确认更改」用到这些模组时，它们会从原机器的排布中移出。之后可随时重新锁定。
- 单次优化超过 100 件时，自动先排除带「过载」「退化」的模组；仍超出才提示手动锁定。
- 所有确认弹窗使用与界面一致的窗口样式（`askConfirm`），不再使用浏览器原生弹窗。

### 必选置顶

- 勾选「必选」的模组在候选栏置顶（仅次于模组舱中点选的那件），带高亮外框与「必选 · 置顶」标签。
- 模组一旦被锁定（手动「锁定一个」或批量锁定），自动取消必选，置顶与高亮随之消失；锁定的条目任何时候都不带必选。
- 超过 100 件自动排除过载/退化模组时，跳过必选件。

### 退化对冲

- 游戏逻辑（`ModuleEffectHelper.Degrade` / `OnUsedLearningAlgo`）：退化模组每次使用，每项为正的基础属性 −1（不低于 0）；自学习模组每次使用，每项低于成长上限的属性 +1（上限读自存档 `LEARNING_ALGO_MAX_*`，没有上限的属性上限为 0，因此为负的属性会回升到 0）。
- 优化比较顺序：目标分数 → 带退化/过载的件数更少 → 未被对冲的退化点数更少。即分数相同、风险件数相同时，优先选用与退化同属性、未满上限的自学习模组，数量尽量对等；不会为了对冲牺牲分数。
- 已退化到 0 的属性不再计入；已满上限的自学习不算对冲；手动添加的自学习模组没有成长上限数据，不参与对冲；从存档导入的会自动带上上限。
- 结果面板在布局含退化模组时显示每项属性的「退化 / 自学习」点数与剩余未对冲点数。
